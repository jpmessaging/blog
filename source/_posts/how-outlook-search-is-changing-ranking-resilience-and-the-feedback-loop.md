検索の品質は説明するのは簡単ですが、実現するのは簡単ではありません。利用者は、送信者やフレーズ、メッセージを受信したおおよその時期を覚えていても、インデックスが想定する正確な用語を覚えているとは限りません。システムには、大規模でノイズの多いメールボックスから適切な候補を取得し、適切に順位付けして、すばやく応答することが求められます。

お客様からのフィードバックを注意深く確認し、検索エクスペリエンスが期待に応えられていない点や、改善できる点を調べてきました。フィードバックとエンジニアリング上のシグナルを合わせることで、特に重要な領域に注力できました。ここ数か月、Outlook チームは検索の 3 つの課題、つまり検索結果のランキングの改善、接続状態が悪いときの検索の回復性の向上、ユーザー エクスペリエンスとエンジニアリング上のシグナルを結ぶフィードバック ループの強化に取り組んできました。ここでは、変更内容とその技術的な背景、次にテストする内容を紹介します。

## 1. ユーザーが確認できる変更

### 関連性に基づく検索結果の表示件数を拡大

**ランキング システムでは、検索結果が日付順に切り替わる前に、関連性が高いと考えられる項目をより多く表示できるようになりました。**

Outlook では、関連性に基づいて順位付けされた検索結果を上位に最大 7 件表示し、その後に残りの検索結果を日付順に表示するようになりました。ランキングでは、メッセージの新しさ、送信者、過去の操作履歴などのシグナルを考慮します。関連性に基づく検索結果の表示件数を増やすことは表示方法の変更ですが、ランキングの品質を評価する対象も広がります。ランキング ロジックと、関連性に基づく表示から日付順に切り替わる境界の両方を引き続き調整しながら、その他の並べ替えオプションも利用できるようにしています。

**利用可能な環境:** サブスクリプション版の従来の Outlook for Windows (従来の Outlook) の Current Channel および Monthly Enterprise Channel、Outlook on the web、新しい Outlook for Windows (新しい Outlook)、Outlook for Mobile で利用できます。Outlook for Mac では 11 月に展開予定です。商用環境とコンシューマー向けの両方で利用できます。

*従来の Outlook for Windows で、関連性に基づく検索結果が従来の 3 件から最大 7 件に拡大した比較画像。*

### クラウド優先の検索と自動ローカル フォールバック

**オンライン時には一貫した機能を提供し、ネットワークが不安定なときには適切に機能を縮退させることを目指しています。**

従来の Outlook は Microsoft のクラウド検索サービスと Windows Desktop Search を組み合わせています。Windows Desktop Search は PC 上のローカル インデックスを管理します。これまで、Find Related、一部の高度な検索構文、より多くの言語でのクエリなど、特定の種類のクエリはローカル検索に限定されていました。対象となる検索では、他の Outlook クライアントと同じ検索機能やサービス側の改善を活用できるよう、クラウド サービスを使用するようになりました。オフライン時や、PST ファイル、POP アカウント、IMAP アカウントなどクラウドに保存されていないコンテンツを検索する場合は、引き続きローカル検索が必要です。クラウド サービスから時間内に応答がない場合、従来の Outlook の検索では接続状態やサービスの待ち時間に応じて、自動的にローカル インデックスにフォールバックするようになりました。

**自動フォールバックを利用できる環境:** サブスクリプション版の従来の Outlook for Windows の Current Channel、Outlook for Mobile、Outlook for Mac で利用できます。新しい Outlook では開発中です。

![接続状態やサービスの待ち時間によって、従来の Outlook の検索がローカル インデックスに自動的にフォールバックすることを示す画像](local-fallback.png)

*接続状態やサービスの待ち時間によって、従来の Outlook の検索がローカル インデックスに自動的にフォールバックします。*

### 待ち時間の改善

平均的な待ち時間も重要ですが、特に遅い検索が、検索の信頼性に対する印象を大きく左右します。

従来の Outlook の検索で、特に遅い 5% の検索に大きな改善をもたらした変更が 2 つあります。

**認証経路の最適化:** 商用メールボックスでは、特に遅い 5% の検索の待ち時間が 40% 短縮されました。

**クラウド検索への移行:** ローカル インデックスからクラウドに移行した種類のクエリでは、特に遅い 5% の検索の待ち時間が 4.5 秒から 1.3 秒に短縮されました。

**利用可能な環境:** サブスクリプション版の従来の Outlook for Windows の Current Channel および Monthly Enterprise Channel で利用できます。商用環境とコンシューマー向けの両方で利用できます。

予定表検索スポットライトでは、一致するイベントを予定表ビューに直接表示します。検索結果の前後にあるイベントや予定の重なりも、検索結果と同じくらい役立つ場合があります。ワンクリックで従来のリスト表示に戻すこともできます。

**利用可能な環境:** Outlook on the web と新しい Outlook for Windows で 11 月から展開予定です。商用環境とコンシューマー向けの両方で利用できます。Outlook クライアント全体への展開を拡大する前に、フィードバックを評価しています。

## 2. ランキングの評価と改善方法

### 検索の改善を測定する方法

検索の改善を本番環境に展開する前に、再現可能な評価が必要です。

まず、実際の企業の受信トレイの特徴を再現するように生成したメールボックスを使って、オフライン テストを実施します。メールボックスには、数千件のメッセージ、会議出席依頼、ニュースレター、グループ メール、複数のプロジェクトにまたがるトピックを含めます。生成データを使うことで、お客様のメールボックスをテスト用のデータとして使うことなく、制御された再現性のあるテストができます。

評価セットには、正解が分かっている数千件のクエリが含まれます。その分布は、キーワード、名前、メール アドレス、それらの組み合わせなど、実際の検索パターン数千件を参考にしています。オフライン評価は改善の反復に役立ちますが、すべてのメールボックスや検索意図を再現することはできません。そのため、広範な展開の前に、制御されたライブ実験とオンライン品質指標を使って変更を検証します。

### Outlook の規模に対応したランキング モデルの蒸留

より優れたセマンティック ランキングも、Outlook の規模で利用されるサービスの待ち時間とスループットの制約を満たさなければ役に立ちません。

Outlook 専用の小規模言語モデルによるランカーを開発しています。このモデルは蒸留によってトレーニングします。大規模モデルが小規模モデルに教師信号を与え、小規模モデルを Outlook のパフォーマンス要件の範囲内で実行できるようにします。エンジニアリング上の目標は、モデル単体の品質だけではありません。本番環境の負荷のもとで、関連性と待ち時間のバランスを改善することです。初期のオフライン結果は有望で、現在、社内テストを実施しています。

この取り組みと並行して、「the」「and」「is」などのストップ ワードをより適切に処理するなど、サービスにいくつかの小さな変更を展開しました。このストップ ワードの改善は、検索の約 3% に影響しました。これらの検索では、ユーザーがメールを開いて操作した結果のクリック数が増加しました。

**ストップ ワード処理を利用できる環境:** すべての Outlook エンドポイントで利用できます。商用環境とコンシューマー向けの両方で利用できます。

![大規模な教師モデルの関連性スコアを模倣する小規模な Outlook 専用生徒ランカーを蒸留でトレーニングし、本番環境の待ち時間要件を満たす仕組みを示す画像](ranking-distillation.png)

*知識の蒸留では、大規模な教師モデルの関連性スコアを模倣する小規模な Outlook 専用の生徒ランカーをトレーニングし、本番環境の待ち時間要件を満たします。*

## 3. 指標とユーザーの意図とのギャップを埋める

Outlook では、検索結果ページに高評価または低評価のプロンプトを表示するようになりました。適切な診断コンテキストと組み合わせることで、このシグナルは、調査が必要なクエリの種類や検索結果のパターンをエンジニアが特定するのに役立ちます。特に重要な点として、検索結果を開いたり読んだりしたといった行動指標は成功を示していても、ユーザーは検索が失敗したと報告する場合があります。明示的なフィードバックによって、代理指標ではユーザーの意図を捉えられないケースを把握できます。

**利用可能な環境:** Exchange Online アカウントと Outlook.com アカウントで利用するサブスクリプション版の従来の Outlook for Windows の Current Channel、Outlook on the web、新しい Outlook for Windows、Outlook for Mobile、Outlook for Mac で利用できます。11 月と 12 月に、より多くの Outlook Search 画面に高評価または低評価のプロンプトを追加する予定です。商用環境とコンシューマー向けの両方で利用できます。

![製品内のフィードバック プロンプトが、診断コンテキストとともに明示的な品質シグナルを取得する画像](search-feedback.png)

*製品内のフィードバック プロンプトは、診断コンテキストとともに明示的な品質シグナルを取得します。*

検索結果が意図と合わない場合は、高評価または低評価のプロンプトでお知らせください。企業のメールボックスは、使われる語彙、コミュニケーション パターン、保存期間の履歴、組織構造がそれぞれ大きく異なります。同じクエリでもユーザーによって期待する検索結果が異なる場合や、同じメッセージをまったく異なる情報から思い出す場合があります。そのため、検索は固定の到達点を持つ機能ではなく、継続的に取り組むシステム上の課題です。検索結果が意図に合わない場合、高評価のシグナルから、クリック数や閲覧時間だけでは得られない情報を把握でき、次の調査の優先順位付けに役立ちます。
